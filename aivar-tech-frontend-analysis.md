# Frontend Reverse-Engineering Analysis — aivar.tech

**Target:** https://www.aivar.tech/
**Analysis date:** 13 June 2026
**Method:** Server-rendered HTML inspection of all publicly accessible pages, asset/CDN analysis, meta-tag and markup-pattern detection.
**Goal:** Documentation detailed enough that a frontend team could rebuild a visually and functionally similar site in React + Next.js + Tailwind CSS.

> **Evidence labelling used throughout**
> **[Confirmed]** — directly observable in HTML, headers, asset URLs, or meta tags.
> **[Strong indicator]** — highly likely based on multiple consistent signals.
> **[Inferred]** — a reasonable reconstruction assumption for the React/Tailwind rebuild; not observed on the live site.
>

## 1. Executive Summary

Aivar (Aivar Innovations) is an AI-services / "co-build AI studio" company. The marketing site is a polished, dark-themed, single-brand corporate site of roughly nine primary pages plus a CMS-driven case-studies collection. Visually it leans on a "governed / engineered / terminal" aesthetic: angular bracket labels (`< SECTION NAME >`), corner-accent SVG decorations on nearly every card, a near-black background, a single bright accent color, GIF/SVG product visualizations, and animated logo marquees.

**The single most important technical finding:** the site is built and hosted on **Webflow** (`meta-generator: Webflow` on every page; all assets served from `cdn.prod.website-files.com`; a `*.webflow.io` staging domain leaks in several links). This means the live front end is Webflow's generated HTML/CSS plus jQuery and Webflow's interactions runtime — **not** a React/Next.js/Tailwind application. That does not reduce the value of a component-level analysis: the visual system is highly regular and componentized, and maps cleanly onto a React + Tailwind rebuild, which this document specifies in full.

The design system is consistent and disciplined: one accent color, a tight set of card archetypes (decorated "panel" cards with four corner SVGs), a recurring eyebrow-label pattern, a five-phase "How it works" timeline reused across pages, repeated trust/logo strips, and a single contact form. Several sections still contain placeholder "lorem ipsum"-style copy ("Norem ipsum", "Borem ipsum", "Jorem ipsum"), indicating the site is recently launched / partially in progress — relevant for anyone rebuilding from it, since some content is not final.

**Rebuild feasibility:** High. The layout is grid/flex based, the component vocabulary is small and repeated, and the interactions (accordion, tabs, marquee, reveal-on-scroll, mobile nav, cookie banner) are all standard patterns. A Next.js (App Router) + Tailwind + Framer Motion implementation would reproduce it faithfully.

## 4. Design System Documentation

> Colors and exact type tokens below are **[Inferred]** from the rendered dark aesthetic and standard Webflow class output, since computed CSS values were read from the rendered design rather than a published token file. They are calibrated to match the observed look and are intended as rebuild tokens. Structure, hierarchy and patterns are **[Confirmed]** from the markup.

### 4.1 Colors

The palette is a dark, near-monochrome "engineering terminal" scheme with a single dominant accent.

| Role | Token (suggested) | Value (inferred) | Usage |
|---|---|---|---|
| Background (base) | `--bg` | `#05060A` – `#0A0B10` (near-black) | Page background |
| Surface / card | `--surface` | `#0E1017` | Panels, cards |
| Surface elevated | `--surface-2` | `#14171F` | Hover / nested cards |
| Border / hairline | `--border` | `rgba(255,255,255,0.08)` | Card edges, dividers |
| Primary text | `--text` | `#F5F7FA` (off-white) | Headings, body |
| Muted text | `--text-muted` | `#9BA1AD` | Secondary copy, eyebrows |
| Accent (primary) | `--accent` | a single bright hue (cyan/electric-blue or lime-green family) | CTAs, bracket labels, icons, list bullets, links |
| Accent hover | `--accent-600` | darker shade of accent | Button hover |
| Success | `--success` | green | Form "submission received" |
| Error | `--error` | red | Form error message |

> The accent appears in the `< … >` bracket eyebrow labels, the `>`/`>>` chevron list markers, primary buttons, and link arrows. There is effectively **one** accent; the design avoids a multi-color palette. **[Strong indicator from the consistent single-accent treatment across all pages.]**

### 4.2 Typography

- **Heading hierarchy [Confirmed from markup]:** clear and consistent use of `h1` (page hero title), `h2` (section titles), `h3` (sub-section / card group titles), `h4` (product/accelerator names, phase titles), `h5` (card titles, stats, team roles). Eyebrow labels (`< SECTION >`) are small uppercase text, not headings.
- **Font family [Inferred]:** a modern geometric/grotesque sans for headings and body (e.g. a Webflow-hosted font such as *Inter*, *Space Grotesk*, *Satoshi*, or similar). A monospace-flavored treatment is implied by the bracket/terminal labels and `>>` markers, possibly a mono font for those eyebrows. Rebuild suggestion: `Inter`/`Geist` for UI + `Geist Mono`/`JetBrains Mono` for eyebrow/terminal accents.
- **Weights:** Headings heavy (600–800); body regular (400); eyebrows uppercase, letter-spaced, 500–600.
- **Heading scale (inferred rebuild):** H1 ~clamp(2.5rem, 5vw, 4.5rem); H2 ~clamp(2rem, 3.5vw, 3rem); H3 ~1.5rem; H4 ~1.25rem; H5 ~1rem; body ~1rem–1.125rem; eyebrow ~0.75rem uppercase.
- **Line heights:** tight on display headings (~1.05–1.15), comfortable on body (~1.5).

### 4.3 Spacing & Layout

- **Grid system [Strong indicator]:** Webflow flex/grid utilities. Sections are full-width with a centered content container. Card groups use 2-, 3-, and multi-column grids that collapse to single column on mobile.
- **Container width [Inferred]:** ~1200–1280px max content width, centered, with generous horizontal page padding (~5–8vw).
- **Section rhythm [Inferred]:** large vertical padding between sections (~96–160px desktop, ~56–80px mobile).
- **Card internal padding [Inferred]:** ~24–40px.
- **Signature decoration:** almost every card/panel carries **four small corner SVGs** (`left-top`, `right-top`, `bottom-left`, `bottom-right`, plus variants `sstl/sstr/ssbl/ssbr`, `b-tl/b-tr/b-bl/b-br`, `edge (1..4)`) absolutely positioned at the corners to create a "framed/engineered" look. This is the most repeated visual motif on the entire site. **[Confirmed — these exact SVG filenames recur on every page.]**

### 4.4 UI Patterns

- **Buttons:** Primary solid accent button ("Book a Call", "Talk to a builder", "Build With Us"); secondary/ghost text-with-arrow link ("View Details", "READ Case Study →", "See our work"). **[Confirmed]**
- **Eyebrow labels:** `< SECTION NAME >` and `>> TIMELINE … <<` — uppercase, accent color, bracket-wrapped. A defining brand element. **[Confirmed]**
- **List markers:** chevron `>` lines (accelerator bullet points) and small SVG bullet icons (`wwb-point.svg`, `w-list-icon.svg`, `solution-list-icon.svg`, `Icon (4).svg`). **[Confirmed]**
- **Cards:** framed panels with corner accents, optional icon/illustration, title, body, and sometimes a list + CTA. **[Confirmed]**
- **Badges/Logos:** certification/partner badges (ISO 27001, SOC 2 / AICPA, CrowdStrike, AWS Partner, MongoDB, NVIDIA) and client/investor logo strips. **[Confirmed]**
- **Navigation:** sticky top navbar with a dropdown "Accelerators" mega-menu; mobile hamburger → full nav with expandable Services/Industries/Accelerators groups. **[Confirmed]**
- **Inputs:** standard text inputs, a select ("How can we help you?" with options Sales/Partnerships/Careers/Press/Security), submit button; native Webflow success and error states. **[Confirmed]**

## 7. Technology Stack Analysis

### Confirmed findings
- **Site builder / CMS / host: Webflow.** Every page carries `<meta name="generator" content="Webflow">`. Page titles are Webflow-style ("Home | Aivar", "Solution | Convogent AI"). **[Confirmed]**
- **Asset CDN: Webflow's `website-files.com`.** All images/SVG/GIF/MP4/WEBP load from `https://cdn.prod.website-files.com/<site-id>/...`. **[Confirmed]**
- **Staging domain: `aivar-tech.webflow.io`** leaks in several "READ Case Study" links on the Convogent page — definitive Webflow fingerprint. **[Confirmed]**
- **CMS Collections:** Case Studies is a Webflow CMS collection — dynamic item URLs and a Webflow collection-pagination param `?1302351a_page=2`. **[Confirmed]**

- **Responsive image formats:** SVG-first iconography, GIF for animation, MP4 hero video, WEBP world map. **[Confirmed]**

### Strong indicators
- **JavaScript runtime: jQuery + Webflow's `webflow.js`.** Webflow sites ship jQuery and Webflow's interactions/IX2 bundle by default; the marquee, dropdown, tabs, accordion, slider, and scroll reveals are almost certainly **Webflow Interactions (IX2)**, not a JS framework. **[Strong indicator — standard for the platform]**
- **CSS: Webflow-generated CSS** (a per-site stylesheet with Webflow utility + custom combo classes), **not** Tailwind or Bootstrap. **[Strong indicator]**
- **Animation: Webflow Interactions** for scroll/hover/loop; GIF/MP4 for the "fancy" motion. No evidence of GSAP/Framer/Lottie in markup, though a custom embed can't be ruled out. **[Strong indicator]**
- **Sliders/carousels:** Webflow's native Slider component (duplicated track nodes seen in HTML). **[Strong indicator]**

There is no `__NEXT_DATA__`, no React root/hydration markers, no Vue/Nuxt artifacts, and no Tailwind class signatures in the served markup. The fully-formed semantic HTML + Webflow generator tag is conclusive. **[Confirmed negative]**

## 13. Accessibility Audit

Observed structure is reasonable but typical Webflow gaps likely exist. Treat the following as a rebuild checklist (status = **[Inferred]** unless noted):

- **Headings:** Generally good hierarchy (single H1 per page, H2 sections). **[Confirmed in markup]** — but watch decorative use of H5 for stats/labels; consider non-heading elements where text isn't a true heading.
- **Images:** Many decorative corner/edge SVGs are rendered as `<img>` with empty/auto alt — ensure they're `aria-hidden`/`alt=""`. Logos and meaningful images need real `alt`. **[Rebuild requirement]**
- **Landmarks:** add `<header>`, `<nav>`, `<main>`, `<footer>` landmarks and a skip-link.
- **Interactive widgets:** Mega-menu, tabs, accordion, mobile nav need `aria-expanded`/`aria-controls`/`role` semantics and full keyboard operation + focus management/trap.
- **Forms:** ensure `<label>` association, `aria-required`, `aria-invalid`, and `aria-live` for the success/error messages (the visual text exists; programmatic association should be verified).
- **Motion:** honor `prefers-reduced-motion` for the hero video, GIFs, and marquee.
- **Contrast:** muted gray text on near-black should be checked against WCAG AA (4.5:1) — light-gray-on-dark can fail for small text.
- **Color reliance:** accent-only cues (links/markers) should also have non-color affordances.
- **Focus visibility:** provide a clear focus ring on the dark theme.
